# Инструменты проекта WorldLoom

Скрипты для сбора исходников, удаления пустых файлов и построения структуры проекта.

Все команды ниже выполняются в PowerShell из корня проекта WorldLoom. Используется Python из активного окружения. Дополнительные библиотеки для этих инструментов устанавливать не требуется.

## Краткий справочник

| Скрипт | Назначение |
| --- | --- |
| `tools/context_pack.py` | Собирает содержимое выбранных исходников в один TXT |
| `tools/delete_empty_files.py` | Находит файлы размером 0 байт и удаляет их только при передаче `--delete` |
| `tools/project_tree.py` | Строит текстовое дерево проекта с учётом файла исключений |

Получить справку по параметрам:

```powershell
python tools/context_pack.py --help
python tools/delete_empty_files.py --help
python tools/project_tree.py --help
```

## 1. Сбор исходников — context_pack.py

### Назначение

Объединяет разрешённые текстовые исходники в общий TXT-пакет, например для передачи на аудит.

Поддерживает два отдельных режима:

- сбор файлов из списка;
- сбор файлов из указанного каталога.

Исходные файлы не изменяются. Готовые пакеты сохраняются в `context_exports`.

### Сбор файлов из списка

В корне проекта создай `context_files.txt`:

```text
backend/app/application.py
backend/app/core/settings.py
frontend/templates/base.html
frontend/src/styles/style.scss
```

Каждая строка содержит путь к отдельному файлу относительно корня проекта.

Предварительная проверка:

```powershell
python tools/context_pack.py --root "." --list "context_files.txt" --dry-run
```

Сохранение пакета:

```powershell
python tools/context_pack.py --root "." --list "context_files.txt"
```

Важно: каталоги в `context_files.txt` текущей версией не поддерживаются. Строка `backend/` приведёт к ошибке. Для каталога используй режим `--directory`.

### Сбор каталога

Только файлы непосредственно внутри `backend`:

```powershell
python tools/context_pack.py --root "." --directory "backend" --dry-run
```

С учётом всех вложенных каталогов:

```powershell
python tools/context_pack.py --root "." --directory "backend" --recursive --dry-run
```

Сохранение пакета:

```powershell
python tools/context_pack.py --root "." --directory "backend" --recursive
```

Параметры `--list` и `--directory` нельзя использовать одновременно.

### Параметры

| Параметр | Описание |
| --- | --- |
| `--root` | Корень проекта; обязательный параметр |
| `--list` | Путь к файлу-списку относительно корня |
| `--directory` | Путь к каталогу относительно корня |
| `--recursive` | Включает подпапки; применяется только с `--directory` |
| `--dry-run` | Проверяет состав и размер пакета без сохранения |
| `--max-bytes` | Ограничение размера в байтах; по умолчанию 2 000 000 |

Пример изменения ограничения размера:

```powershell
python tools/context_pack.py --root "." --directory "backend" --recursive --max-bytes 4000000 --dry-run
```

### Ограничения и проверка результата

- Используются разрешённые скриптом имена и расширения.
- Исходники должны соответствовать проверке UTF-8.
- В режиме каталога ссылки и Windows reparse point пропускаются.
- Запрещённые каталоги и неподдерживаемые файлы пропускаются с сообщением.
- Ошибки чтения выбранных исходников и превышение размера останавливают сборку.
- Минифицированные файлы отдельно не исключаются.
- `context_exports` исключён из сбора.

Сначала запускай `--dry-run`, проверяй список включённых файлов и причины пропусков. Затем повторяй команду без этого флага.

Перед передачей пакета просмотри его содержимое: фильтрация имён не гарантирует отсутствия паролей, токенов и других секретов внутри исходников.

### Особенности списка исходников

- Пустые строки и строки, начинающиеся с `#` после удаления крайних пробелов, пропускаются.
- Повторное указание одного и того же разрешённого пути не добавляет файл в пакет повторно.
- Порядок файлов соответствует первому появлению в списке.
- Пути записываются без обрамляющих кавычек.
- Маски и каталоги в списке не поддерживаются.
- Ошибка в выбранном пути останавливает сборку, а не просто исключает проблемную строку.

### Сбор от корня проекта

Для сбора разрешённых файлов из корня и вложенных каталогов:

```powershell
python tools/context_pack.py --root "." --directory "." --recursive --dry-run
```

После проверки состава:

```powershell
python tools/context_pack.py --root "." --directory "." --recursive
```

Этот режим может включить много файлов. Для точечной задачи предпочтительнее список или конкретный каталог.

### Фильтрация и размер

- Пути к исходникам должны находиться внутри корня проекта; абсолютные пути и компоненты `..` не принимаются.
- Имена, начинающиеся с `.env`, запрещены, включая `.env.example`.
- `.gitignore` не читается, а файл `.gitignore` не проходит текущий фильтр разрешённых расширений.
- Файлы проверяются как UTF-8 с допустимым BOM; содержимое в пакет включается в исходных байтах.
- В режиме каталога файлы сортируются по относительным путям.
- Ограничение `--max-bytes` применяется к каждому читаемому файлу, сумме выбранных исходников и итоговому пакету с заголовками. Файл-список также проверяется на индивидуальный размер.
- Поэтому сумма размеров исходников может укладываться в ограничение, а готовый пакет — уже нет.
- Проверяется изменение состояния файлов до и после чтения; обнаруженное изменение останавливает сборку.

### Формат результата

Пакет содержит:

- время сборки в UTC;
- список включённых файлов;
- относительный путь каждого исходника;
- размер исходника в байтах;
- контрольную сумму SHA-256;
- содержимое файла между разделителями.

Каждый запуск без `--dry-run` создаёт отдельный файл в `context_exports`. Имя включает время UTC и случайный суффикс.

Фильтры не анализируют смысл исходного кода и не гарантируют отсутствие секретов. Перед передачей пакета обязательно просмотри его содержимое.

## 2. Удаление пустых файлов — delete_empty_files.py

### Назначение

Находит обычные файлы размером строго 0 байт.

По умолчанию работает только в режиме просмотра. Удаление выполняется исключительно при передаче `--delete`; отдельного интерактивного подтверждения скрипт не запрашивает.

Файл, содержащий хотя бы пробел или перевод строки, пустым не считается. Пустые каталоги не удаляются.

### Проверка без удаления

Проверить только файлы непосредственно внутри `backend`:

```powershell
python tools/delete_empty_files.py "backend"
```

Проверить также вложенные каталоги:

```powershell
python tools/delete_empty_files.py "backend" --recursive
```

В выводе будут перечислены кандидаты на удаление и итоговые счётчики. Без `--delete` файлы остаются на месте.

### Исключения

Параметр `--exclude` исключает точное имя файла, а не путь и не маску.

Например, сохранить все пустые `__init__.py` и `.gitkeep` в проверяемых каталогах:

```powershell
python tools/delete_empty_files.py "backend" --recursive --exclude "__init__.py" --exclude ".gitkeep"
```

Каждое исключение указывается отдельным параметром. На Windows сравнение имён выполняется без учёта регистра.

Записи вида `backend/__init__.py` не принимаются. Запись `*.py` не работает как маска.

Встроенных исключений нет: даже `__init__.py` необходимо исключать явно.

### Удаление

Сначала выполни предварительную проверку:

```powershell
python tools/delete_empty_files.py "backend" --recursive --exclude "__init__.py" --exclude ".gitkeep"
```

Если список подходит, повтори команду с `--delete`:

```powershell
python tools/delete_empty_files.py "backend" --recursive --exclude "__init__.py" --exclude ".gitkeep" --delete
```

Удаление выполняется напрямую, без перемещения в корзину. Перед ним желательно сохранить нужные файлы в Git или сделать резервную копию.

### Параметры

| Параметр | Описание |
| --- | --- |
| `directory` | Обязательный позиционный аргумент: каталог для проверки |
| `--recursive` | Проверять также вложенные каталоги |
| `--exclude NAME` | Исключить точное имя файла; можно передавать несколько раз |
| `--delete` | Удалить найденные пустые файлы; без него выполняется только просмотр |

### Ограничения и меры предосторожности

- Символические ссылки и Windows reparse point пропускаются.
- Если путь к исходному каталогу проходит через такую ссылку, запуск завершается ошибкой.
- Перед удалением повторно проверяются тип, размер и идентичность файла.
- Изменившийся файл пропускается с сообщением.
- Ошибки обработки выводятся в консоль; проверка остальных доступных объектов продолжается.
- `.gitignore` не читается.
- Автоматических исключений для `.git`, `venv`, `node_modules` и других служебных каталогов нет.

Не запускай рекурсивное удаление от корня проекта без внимательной проверки. Лучше выбирать конкретную папку с исходниками: скрипт может удалить нужные пустые файлы-заготовки, маркеры и служебные файлы.

## 3. Дерево проекта — project_tree.py

### Назначение

Строит текстовое дерево каталогов и файлов с учётом отдельного файла исключений.

Содержимое исходных файлов не читается и не изменяется. Результат сохраняется в UTF-8.

По умолчанию используются:

- корень — текущий каталог;
- файл исключений — `structure_ignore.txt`;
- результат — `structure.txt`.

Обход вложенных каталогов выполняется автоматически: отдельного параметра `--recursive` у этого скрипта нет.

### Подготовка исключений

Перед первым запуском создай в корне проекта `structure_ignore.txt`, например:

```text
# Служебные каталоги и зависимости
.git/
venv/
.venv/
env/
node_modules/

# Кэш
__pycache__/
.pytest_cache/
.mypy_cache/
.ruff_cache/
.cache/

# Результаты сборки и локальные выгрузки
/frontend/dist/
/context_exports/
/logs/

# Файлы окружения
.env
.env.*

# Временные файлы
*.log
*.pyc
```

Файл исключений должен существовать даже тогда, когда исключения не нужны. В этом случае оставь его пустым.

### Формат правил

Это собственный формат скрипта, а не полноценный синтаксис `.gitignore`.

| Правило | Действие |
| --- | --- |
| `node_modules/` | Исключить каталоги с таким именем на любой глубине |
| `*.log` | Исключить объекты, имя которых соответствует маске, на любой глубине |
| `/frontend/dist/` | Исключить конкретный каталог относительно выбранного корня |
| `/data/local.json` | Исключить конкретный файл относительно выбранного корня |
| `# комментарий` | Строка игнорируется |
| Пустая строка | Строка игнорируется |

Особенности:

- Для путей используй `/`, а не `\`.
- Путь из нескольких компонентов должен начинаться с `/`.
- Правило без начального `/` сопоставляется с именем объекта, а не с полным относительным путём.
- Завершающий `/` ограничивает правило каталогами.
- Правила с начальным `/` сравниваются с относительным путём точно, без раскрытия масок.
- Для правил без начального `/` поддерживаются маски fnmatch, например `*` и `?`.
- На Windows сравнение выполняется без учёта регистра.
- Исключённые каталоги не обходятся.
- Возврат файлов через `!` не поддерживается.

Например, `!.env.example` не вернёт шаблон в дерево после исключения `.env.*`. Не копируй `.gitignore` целиком без проверки совместимости правил.

### Первый запуск

Из корня проекта:

```powershell
python tools/project_tree.py
```

Или с явным указанием всех путей:

```powershell
python tools/project_tree.py --root "." --ignore "structure_ignore.txt" --output "structure.txt"
```

Сам файл результата в дерево не включается.

### Обновление существующего дерева

По умолчанию скрипт отказывается перезаписывать существующий результат.

Для обновления добавь `--overwrite`:

```powershell
python tools/project_tree.py --overwrite
```

Для создания отдельного варианта:

```powershell
python tools/project_tree.py --output "structure_review.txt"
```

### Дерево отдельной папки

```powershell
python tools/project_tree.py --root "backend" --ignore "../structure_ignore.txt" --output "../backend_structure.txt"
```

В этом примере:

- корнем дерева становится `backend`;
- правила читаются из файла в корне проекта;
- результат сохраняется рядом с папкой `backend`.

Пути с начальным `/` в правилах всегда отсчитываются от выбранного `--root`. Поэтому при смене корня набор правил может потребоваться скорректировать.

### Параметры

| Параметр | Описание |
| --- | --- |
| `--root` | Корневой каталог дерева; по умолчанию `.` |
| `--ignore` | Файл исключений; по умолчанию `structure_ignore.txt` |
| `--output` | Файл результата; по умолчанию `structure.txt` |
| `--overwrite` | Разрешить перезапись существующего результата |

Пути `--ignore` и `--output` могут быть абсолютными или относительными. Относительные пути отсчитываются от `--root`.

Родительская папка результата должна существовать: скрипт не создаёт её автоматически.

### Проверка результата

- Каталоги выводятся перед файлами.
- Внутри группы объекты сортируются по имени.
- Встреченные ссылки и Windows reparse point отмечаются как ссылки и не обходятся.
- Файл результата не может совпадать с файлом исключений.
- При ошибке доступа или обхода скрипт сообщает об ошибке и не завершает построение дерева успешно.

Дерево содержит только имена и пути, но они тоже могут раскрывать внутреннюю структуру проекта. Перед передачей проверь результат.

## 4. Общие правила работы

### Gitignore и исключения скриптов — разные механизмы

Ни один из этих скриптов автоматически не использует `.gitignore`.

| Инструмент | Откуда берутся исключения |
| --- | --- |
| `context_pack.py` | Из встроенных ограничений имён, каталогов и расширений |
| `delete_empty_files.py` | Только из переданных `--exclude` |
| `project_tree.py` | Из файла, выбранного через `--ignore` |

Добавление папки в `.gitignore` не исключает её автоматически из обхода этими инструментами.

### Что сохранять в Git

Обычно стоит сохранять:

- исходники трёх скриптов;
- `commands_tools.md`;
- `structure_ignore.txt`;
- `context_files.txt`, если это общий список для работы над проектом.

Локальные результаты можно исключить:

```text
/context_exports/
/structure.txt
/structure_review.txt
/backend_structure.txt
```

Последние два правила нужны только при использовании соответствующих примеров команд.

### Коды завершения

Все три скрипта возвращают:

- `0` — выполнение без зарегистрированных ошибок;
- `1` — ошибка выполнения или обработки;
- `2` — ошибка аргументов командной строки, обнаруженная стандартным парсером.

В PowerShell код последней команды можно проверить:

```powershell
$LASTEXITCODE
```

У `delete_empty_files.py` отсутствие найденных пустых файлов — нормальный результат, а не ошибка.
